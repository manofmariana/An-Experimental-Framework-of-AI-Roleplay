# Ofair 领域词汇表

术语定义与冲突消解的唯一口径。机制细节以 `DESIGN.md` 为准；未实现的规划见 `ROADMAP.md`。

## Language

**Event（事件）**:
真相层唯一记录单元，由 GM 裁决写入；`@CID` 占位，渲染时身份替换。**能且只能携带 `known_by` tags**——GM 标记时已推理过各角色可见性，感知过滤无地点成分、无其他限制 tag。事件存结构化 clock 值，自然语言时间头在注入/显示时按世界包时段映射表机械渲染。**GM 每轮产出的事件数 = 其计划划分的新组数**：普通周期 = 1 个；组分裂/重组时各新组各一个事件。裁决包字段：`events[{text,tags,location?}]` / `narrativity` / `deltas` / `durations` / `location`，且**先写事件、后定 durations/location**——叙事推理自然约束变量分配。写作纪律（提示词协议层，不做程序强校验）：**摘要制**——不完整转述台词、对内容与情节做意义性总结；禁人称代词；保言行顺序、只记已发生；条目记录事实而非视角、禁止重合。
_Avoid_: 记忆条目、聊天记录；"摘要"（提示词层框架叫法，非领域术语）

**World Clock（世界时钟）**:
世界时间落盘唯一表示为 `world.time={y,m,d,h,min}`；逻辑 clock getter 以 y=365d、m=30d 派生绝对分钟，setClock 反写结构时间并记录可逆 `world.time` VarChange。自然语言头为"Y年M月D日·时段"。`time.json.start` 等于初始 world.time，仅保留开局锚与 periods 时段表。
_Avoid_: 回合数、轮次时间

**Timer（到期时刻）**:
**角色变量**——绝对分钟标量（世界纪元起算），调度 = 扫描全体角色取最小到期时刻；`null` = 无计时器（调度永不弹出，等待 GM 结算）。GM 是唯一定立者，但 **GM 不直接写 timer**——GM 只输出时长（Span），程序在 GM 步锚定当前世界时钟一次性折算 `timer = clock + toMinutes(span)`；**系统内部不流通相对值**。注入/显示层把标量机械渲染为自然语言时间，LLM 不见标量。跨轮对齐由注入解决：GM 提示词含派生快照"各角色剩余时间"（占位符 provider 计算）。"组计时器统一" = GM 给出的组时长被程序逐成员折算应用，故必然统一；组本身不持有计时器。
_Avoid_: 倒计时、剩余时间（注入层派生渲染，非变量）；"GM 设定 timer"（GM 给的是时长，到期时刻由程序折算）

**Span（时长）**:
相对时间量 `{y?,m?,d?,h?,min?}`，**只存在于 GM 裁决包契约与提示词中**（`durations: [{cid, span}]`）；角色决策包不含 span。钳制 ≥ 0（`{min:0}` = 立即到期）。采用相对时长而非绝对时刻的原因：GM 看到的是渲染后的自然语言时间，写绝对时刻只能瞎猜，相对时长结构性避免负值/算错。
_Avoid_: duration、偏移量、倒计时

**Character（角色）**:
主控角色（isPlayer=true，缺省 C0）与 NPC 的统称；所有角色状态完全同构：name/gender/age/personality/tags/reaction/location/timer/group/initiative/level/isPlayer/channel/acted/relations/long_term_memory/vars。角色决策包：`inner` 必填（内心活动与意图），`action` 与 `dialogue` 至少其一，关系实际变化时追加 `relations`，调度指令追加 `markers`；角色决策不含时长，Span 仅供 GM 裁决包 `durations` 字段。
_Avoid_: 仅指 NPC；通用 `changes` 字段

**isPlayer**:
角色变量，标记该角色当前由玩家操控；`await_player` 一律按 isPlayer 判定，不硬编码 CID——为切换扮演对象、多人操控角色预留。

**Level（等级）**:
角色必备变量；地点（Location）也带 level。两者差值预留给突发鉴定（未接线，见 `ROADMAP.md`）。

**Location（地点）**:
结构化变量 `{name, level}`——name 是 GM 裁决时赋予的自由文本（以世界包为参考、提示词管理；GM 在全员行动完后推理，会主动让剧情上在一起的角色拿到相同 name），level 是地点等级。同步组的"同地"判定按 name。
_Avoid_: 纯自由文本地点

**Initiative（先攻）**:
周期内行动排序的确定性投掷：d20 + reaction，总值同值即"同时"（同时行动者互不注入）；代码侧执行，不经 LLM。**结果写入角色变量，结构为 {先攻值， 组编号}**——组编号变化时重置（**变为 0 除外**：离场归单人组保留旧值，被召回原组时组编号对上即复用，不重投）；入组时已存值的组编号与当前组一致 → 复用，不一致/为空 → 该成员单独补投插入既有顺序（补投不波及全组）。
_Avoid_: 速度、敏捷判定

**Reaction（反应属性）**:
角色变量，先攻修正值（d20 + reaction）；**可成长**（随角色经历变化），开场全员取同一值。

**Sync Group（同步组）**:
**派生状态，不是变量拥有者**——角色的 **Group 变量 = {组编号， 组位置}**（`组编号=0` = 单人组，恒有值）。**成组 = timer 一致 + location 一致（自动）**；邀请可跨地点并入（见 Invitation）。**组位置总绑定先攻最高者的 CID**（= 其 location；领头者变更则重绑）；**角色入组时自身位置 ≠ 组位置 → 先攻 -1**（远程参与的劣后）。临时概念，随变量变化生灭。**单活跃组不变量**：任意时刻只有一个组在前台行动（DES 串行弹出）；前台组成员结构上不可被联系（联系标记目标只能是后台角色，**后台判定纯按 timer**）。**同一到期时刻弹出多组 → 逐组串行**：按组内最高先攻值降序，同值比该成员 CID 升序；每组跑至 GM 结算为止（**GM 契约：时长必非 0**，成员推入未来后本组自然让位，下一组同刻开跑，不存在"跑多久换组"问题）。后台角色远程入组后，GM 依其行为（如挂断电话）把到期时刻对齐回原组，同地同时自动成组即自然回归原组（组 id 保稳延续原组身份）——回归不需要专门机制。**注入标注**：位置 ≠ 组位置的成员在注入中显式标注（远程参与），对齐计时器靠提示词约束 + 近期事件注入。组 id **指派并保稳**：成员集精确匹配 → 保留原 id；**纯减员 → 剩余成员继承原 id**（分裂则最大子集继承，并列取最小 CID）；**纯增员 → 也继承原 id**（已有成员先攻不变；新成员单独补投插入既有顺序，召回者复用已存先攻值）；**合组 = 人少并入人多**。全新组合 → 未用过的新 id。不能由 hash 派生——连续轮每圈重设 timer 都会换 id，连续场景判定即垮。
_Avoid_: 队伍、场景组；"组持有 location/计时器"（组位置绑定成员 CID，组不持有变量）；"在场组"、"对话组"、"在场/不在场同步组"（旧名）

**Invitation（邀请）**:
拉人入组的唯一通道，由**联系标记**发起（途径字段——电话/视频/远程开门……——与对象列表）。**目标规则：至少含一个异组角色**（异组 = location 不同，或 location 相同但 timer>0 的角色）；**同组目标默认同意**——无组变动、无应答激活，单纯赋予频道变量；目标只能是**后台角色**（前台活跃组成员结构上不可被联系，后台判定纯按 timer）。**生效条件**：邀请标记生效时邀请者必在前台（其组 timer 到期）。**延迟生效**（防止时钟抢跑——立刻归零受邀者 timer 会抢在其旧组行动之前）：联系标记**触发 GM 立即结算**（GM 与受邀者都看不到邀请标记），邀请**与邀请者的 timer 同步生效**（邀请者组下一次弹出时落实），并算作**原周期的补完进程**：异组角色按**原有先攻按序**应答 →（若前台组未变）其他未完行动者补完 → **接受者进组并补投先攻** → 新组获得完整周期；若邀请者组曾进后台：回前台时行动顺序表重置（全员未行动），受邀者应答后直接进组、插入对应先攻位置并标**已行动**（无视先攻次序的优先行动）。**拒绝**（附理由）→ timer **自动还原**为被邀请前的值，不调用 GM，失去频道变量（全体持有者因此同地 → 频道自动清除），**拒绝回复不计入已行动**（随后台重置自动恢复行动权）。**接受**（确认标记 + 首轮回复）→ timer 归当前时钟（立即到期）直到 GM 重设，位置 ≠ 组位置 → 先攻 -1，**首轮回复计入被补完的旧周期已行动**。**感知过滤不在组层做**：组内注入全透传（被拒邀请者的拒绝理由同样组内可见）；跨地点私密性归未来的顶层 TAG 过滤系统（见 `ROADMAP.md`）。
_Avoid_: 对话组、远程组（旧名）；AV 标签位

**Channel（频道）**:
角色变量（number|null），跨地点联系的"通话中"标识。**联系标记生效即分配**给邀请者与全部对象（同一频道 id）；**拒绝者失去**；**退组自动清除**。承担两个职责：①**防重入**——频道持有者不出现在任何联系人列表注入中（通话中/邀请建立中不可再被邀请，pending 与已建立统一处理），且**频道持有者/待答邀请者本身也看不到联系人列表**（占位符整体置空——角色必须从剧情与 relations 中对号 CID）；②**生命周期**——只要有任意两个持有者 location 不同，跨场景视为存在；**全部持有者 location 相同 → 频道变量全部清除**，仍非组位置的持有者直接离场（组归 0）等待下一次 GM 结算。
_Avoid_: 通话状态、房间号

**No-Adjudication Round（无判定轮）**:
周期的**默认形态**——一个行动周期内无人立 GM 请求标记，整个周期即无判定：角色照常输出台词与行为，工作集累积，GM 不激活。行为与台词有其一即可。**GM 激活两种触发**：①**标记触发**——周期内有人立 GM 请求**或联系**标记 → **立即激活**（不等周期末——开门类判定不能等，否则其他角色会基于未裁决状态继续行动；联系标记触发 GM 是为延迟生效的邀请结算到期时刻，见 Invitation；**同先攻批次必须全员行动完才激活**，批内同时性不被裁决撕裂）；②**硬保险**——距上次 GM 激活满 N 个行动周期（可编辑数值）→ 周期末激活；**前台仅 1 人时阈值恒为 1**（单人连续行动不成立，每动必结算）。**立即激活（中途 GM）的时长覆盖契约 = 精确覆盖全体同步组成员 + 刚从同步组离开的成员**（程序强校验：缺少/越界/重复即拒绝重试）。覆盖未行动成员恰恰是周期补完的前提——**周期序列与 timer 无关，是组自身的状态**，acted 变化有且仅有四种：①行动后 → 已行动；②全组已行动 → 全员重置未行动、X+1；③组结算后进后台 → 全员重置未行动、X 归 0；④组减员至单人 → 幸存者重置未行动、X 归 0（减员至单人 = 新独奏节奏起点，避免双人期累积的 X 被单人阈值溯及既往）。未行动成员保持未行动，时长一致则组状态不变、周期不乱；恰恰是 GM 漏给时长才会让他们的到期时刻与已行动者错开、被编入别组、打乱周期。组存续规则：timer 同步 → 组编号存续，行动顺序由 {先攻值，组编号} 派生（同值批内按 CID 升序）。软保险 = 提示词层的退出期望管理。
_Avoid_: 对话轮（旧名）；普通轮

**Marker（标记）**:
角色/玩家输出中的结构化指令位，**DecisionPackage 的可选 `markers` 数组**（每条 `{type, ...params}`：`gm_request` / `leave`（二者互斥）/ `recall{target}` / `contact{channel, targets[]}` / `confirm`），程序只读结构化字段、不做行内文本解析；提示词按结构化格式教学。标记**不进工作集、不进任何注入**——解析后只有即时程序作用（调度/组别/timer 变更），即抛；离开经 `{{departure_notices}}` 占位符通知后续角色，召回/邀请经过暂无注入渲染（见 `ROADMAP.md`）。五种：
- **GM 请求标记**：请求 GM 裁决；**与离开标记二选一**。同先攻批全员行动完后 GM 立即激活（见 No-Adjudication Round）。
- **离开标记**：离场**不触发 GM**——程序当场将其组编号归 0、timer 置 null（无计时器，调度不再弹出；未结算离开判据 = 组归 0 且无计时器，initiative 仍指原组，供召回与离场通知定位）；结算（离场事件、新时长）推迟到下一次 GM 激活（标记触发或硬保险）。**对所有角色（含玩家）统一程序化**；离场者的过去言行继续注入原组（直到 GM 清算）。提示词层约束：独处时不立此标记（全员离场 = 全员无计时器 = 死锁停等）。
- **召回标记**：把已离开且未结算者拉回——timer 归当前时钟（= 组原到期时刻）、按进组规则归组，**先攻不变、发言顺序保持**（复用已存 {先攻值，组编号}，组编号对上即有效）。**跨周期有效**（离开→GM 结算前均为"未结算"）。
- **联系标记**：发起跨地点邀请（途径字段 + 对象列表），机制见 Invitation。
- **确认标记**：被邀请者接受邀请（+ 首轮回复）；拒绝则输出理由、不立此标记，timer 自动还原。
_Avoid_: 指令、命令、工具调用

**Action Cycle（行动周期）**:
连续场景内**所有成员各行动一次**的计数单位；硬保险"GM 强制间隔"以行动周期计（N 个行动周期后强制激活 GM）。与"轮"（单次激活 seq）区分。**周期补完**：前台组不变 ⇒ 已行动/未行动状态不变，未行动者继续行动，直到原周期成员全部行动完，再进入下一周期或被并入新组——保证一个组只要不进入后台就一定能进行完整的周期活动（人少并入人多的组变动发生在补完之后；中途 GM 后未并组、组仍前台 → 未行动者继续，同属补完）。进度管理见 Action Order Table。
_Avoid_: 圈、回合

**Action Order Table（行动顺序表）**:
顺序 = **派生**（只有前台组用得到）← 角色 initiative 变量（{先攻值，组编号}）现排；**已行动位 = 角色 acted 变量**（快照落盘，随 changes 落账、回溯可逆——程序在角色行动后置位，周期完成/后台重置时清零；不做 archive 回扫——恢复时无需判断步骤在不在本周期内）。成员增减兼容：接受者应答即程序置其已行动位（后台回归时 = 无视先攻次序的优先行动，插入对应先攻位置）；离开者从当前成员集移除，完成判定只看当前成员。**周期计数 X = 世界变量**：周期完成 +1，任何 GM 激活后清零；X 达阈值 N → 周期末 GM。中途 GM 的补完自动成立（不动已行动位，无特例）。GM/正文步不参与调度语义。
_Avoid_: 轮游标、pipeline 快照、组级先攻排序存储、archive 回扫定行动状态

**Continuous Scene（连续场景）**:
同一个同步组（同一组编号存续期间）的全部轮次。正文归档记录该轮的 `participants` 与行动时的 `scenes[CID]`；角色正文滑窗只取包含自身且归档场景 id 与当前相同的最近 N 段，GM 只取与本轮行动者连续的正文，正文 agent 保持全量近期正文。
_Avoid_: 按全局最近正文注入

**Working Set（工作集）**:
当前轮未裁决的角色言行暂存区；GM 裁决时才转写为 Event，此前不落事件库。
_Avoid_: 暂存消息、上下文

**Prose（正文）**:
小说视图渲染器的产出；GM 事件经字段提取、提示词组装后注入（"何时何地，哪些人做了什么"），一次 GM 包（N 事件）渲染一次（narrativity 包级控制，skip 则无正文）。注入中 GM 事件**之前**还有：本轮各角色的台词+内心（inner 含意图，随内心一并作为正文情绪参考）。渲染范围 = 全量事件（不按玩家视角过滤）。存储原文带**指称占位符**（见下条）。
_Avoid_: 输出、回复

**Reference Placeholder（指称占位符）**:
正文存储原文中指称演员表角色的占位语法 `[[称呼|@CID]]`——称呼 = 当时为人所知的名字/外号/特征称谓，@CID 绑身份；被引号包裹的直接引语豁免，照写原文。渲染看读者：玩家显示 → 称呼；角色注入 → 按读者 relations（name → impression → 保留 @CID）；GM 注入 → 称呼（@CID）；正文 agent 的上一轮正文注入保持原文（格式学习通道）。与 Event 的 @CID + 身份替换同一"存储用 CID、渲染看读者"体系（adr/0003）。
_Avoid_: 正文裸名直存、正文裸 @CID 直存

## Relationships

- **Sync Group** 是派生状态：程序按 **Character** 变量机械划分（timer+location 一致自动成组；**Invitation** 可跨地点并入）并指派保稳 id；**Group = {组编号， 组位置}**，组位置绑定先攻最高者 CID，组不持有任何变量
- **Timer** 与 **location**（{name, level}）是角色变量；GM 给出的组时长（Span）由程序逐成员折算为到期时刻应用（故组内统一）；独立改某角色的 location/timer 即离组
- **World Clock** 只在调度器弹出最近 Timer 时跳转；全体角色的 Timer 先后顺序 = 轮次顺序（"下一步该谁"）
- 一个 **Action Cycle** 属于一个 **Sync Group**；言行暂存 **Working Set**，GM 激活后转写为 **Event**
- **Event** 的可见性 = `known_by` tags 唯一通道（GM 推理后标记）；location 字段只作叙事记录，不参与感知过滤
- **Prose** 与 **Event** 同一"存储用 CID、渲染看读者"体系：事件身份替换走 relations（renderForReader），正文指称占位符按读者分视图（玩家=称呼 / 角色=relations 过滤 / GM=称呼（@CID））
- **时间轴与轮状态全部派生，无独立存储**：调度 = 扫描角色 Timer 取最小；组 ← timer+location/邀请；行动顺序 ← Initiative 变量（{先攻值， 组编号}）；游标与 phase ← archive 的 seq 序列推断（archive 不存 pipeline 快照）

## Flagged ambiguities

- "轮"易混用：总轮次 seq（一次激活）与行动周期（连续场景内全员各行动一次）——后者一律用 **Action Cycle** 指称。
- "摘要"是 gm.prompt.json 对事件的提示词层叫法，目的是约束 GM 输出（摘要制写作）；领域术语与讨论基础仍是"事件"。
