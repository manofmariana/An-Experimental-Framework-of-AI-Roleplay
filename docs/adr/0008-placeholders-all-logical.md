# 占位符全声明式（无内置代码占位符层）

**决定**：所有占位符统一为声明式数据，**定义读者无关**——名称 + 内容源引用 + 段列；取数范围由投影层按读者供给（角色取在场者、GM/正文取全量），同一占位符跨对象复用。条目段 = 放行/不放行两侧结构：放行框（其中的路径调用 = 该条目允许的调用集）与不放行框各为缺省注入，两侧均可加号追加"匹配记号集 → 文字模板"**精确匹配**分支（键 = 条目匹配记号集 = 各路径 matched 并集，含归一化类别记号与虚拟挂载，见 adr/0007；未命中走该侧缺省兜底）。条目状态 = 放行框全部路径调用放行 → 放行侧，任一不放行 → 不放行侧；不放行侧框内的路径调用照常解析（放行的给值，未放行的给空）。条目遍历序两选项：**前置**（默认，条目轴独立滚完再进下一条目）/**置后**（条目轴插到首位轴之后，与同首位轴的置后条目合并为逐实例组；同一占位符内所有置后条目的首位轴必须一致，编辑期机检）。身份替换不是占位符职责：输出保留 @CID 原文，由组装层按"模板在谁的上下文里组装"统一做读者渲染。代码只保留两个**非占位符**层：内容源投影（取数语义与派生逻辑）与组装后处理（身份替换）。

**为什么不保留内置代码占位符层**：条件分支用"匹配记号集精确匹配 → 模板"即可声明式表达，分层无收益；把渲染留在代码里会让 WebUI（及未来的工具 Agent）无法创造占位符。放行/不放行必须分侧设缺省：无 TAG 广播内容的匹配项恒为空集，与"不放行且无匹配"同形，仅靠匹配项无法区分——status 显式头部由此成为过滤契约的硬要求。遍历序开放后，单个占位符即可完成全体角色变量的自然语言渲染；非角色内容可用单实例嵌套（world.worldname.XXX）使条目轴顺序无意义。真正需要代码的是取数投影（连续场景判定、同先攻批隔离、按读者的取数范围限定）——那是内容源层，不是占位符层。

**代价**：新取数语义（新内容源）仍需代码；声明式解释器需要契约与测试；模板作者需理解匹配记号集（GM/正文的 matched 恒含全知+强制全知）与遍历序语义；编辑期机检（置后条目同轴、路径必须到末端、tag_list 原子即止）是质量闸门。
