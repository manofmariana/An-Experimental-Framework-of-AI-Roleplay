# 抓取先于过滤：TAG 是第二道闸

**决定**：注入系统分两道闸——**第一道闸 = 抓取**：占位符经类别 + 路径声明取哪些内容单元（定义读者无关），取数范围由投影层按读者限定（每个角色在自己的组装里取自己的数），不取即无泄露；**第二道闸 = TAG 过滤**：只对可能被同一抓取覆盖、但应对不同读者区别放行/降级的内容生效。能靠控制抓取对象解决的问题，不动用 TAG。

**为什么不是"一切皆可 TAG 化"**：TAG 化有成本（挂载、安插程序、组合求值），而大量"保密"需求在抓取层已结构性成立——同步组设定决定正文滑窗取给谁、快照类内容只有主人会抓取、同先攻批本来就不互取、GM 强制全知不需要过滤。给这些内容挂 TAG 是把第一道闸的问题错放到第二道闸解决，徒增复杂度还遮蔽真正的归属判断。**例外 = 在场性**：前台/后台可见性无法靠抓取锁定读者（后台角色随时可能被远程联系激活、读者与内容无稳定归属关系），已 TAG 化——角色持 appearance 系统布尔（程序维护），vars 源全量遍历、对后台角色的全部末端虚拟挂载 fappear 六级统一走第二道闸（adr/0002 同体系）；属主 = 读者的子树自豁免不挂载（后台角色被远程联系激活应答时仍读得到自己的变量）。

**代价**：设计新注入时必须先做归属判断（这靠抓取范围能否锁定读者），判断错误会把过滤系统用成摆设或把抓取设计成漏洞；该纪律依赖模板/占位符作者的自觉，无机械校验。
