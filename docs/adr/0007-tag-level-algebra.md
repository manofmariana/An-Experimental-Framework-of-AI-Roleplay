# TAG 逻辑代数：等级表达式，等级是内容侧挂载属性

**决定**：

- **判定式纯内容侧**：内容侧每个 TAG 挂载 = {name, level}，level ∈ {1, 2}（封闭，未来需要更多级再扩）；T =（所有一级 TAG 取 ∨）∧（所有二级 TAG 取 ∨）；空等级组不产生约束；无 TAG 内容判别式为空 = 恒通过（广播语义，不设独立广播/强制广播逻辑）。对象侧 = 纯名称集合（落盘 ∪ 程序派生），无等级——GM 授予/摘除角色 TAG 的裁决包字段 = 纯字符串数组。
- **等级与 TAG 身份解绑**：等级是挂载处的可调属性，不进注册表；结构附加默认一级，GM/世界作者加挂只选"或（一级）/与（二级）"。
- **全知分层 = 虚拟挂载**：求值时（不落盘）对非空等级组追加虚拟 TAG——一级组追加"全知"、二级组追加"强制全知"。GM 与正文持 {全知， 强制全知}；"系统"类角色只持 {全知}——挂有二级实 TAG 的内容对其隐瞒（系统流叙事）。无 TAG 内容无等级组、不追加，恒通过不被虚拟挂载破坏。
- **过滤返回 = {status, content, matched}**：status = pass/fail 显式枚举（不靠空内容推断——放行且内容为空是合法结果）；matched = 双侧共同持有的 TAG 记号集，含虚拟挂载。开放类别归一化：category ∈ {cid, channel, location} 的命中一律报类别固定记号——每角色每类至多持有一个（cid = 自身 CID，唯一；channel = 当前频道编号；location = 当前地点名，后两者程序随变量持久安插），归一化无损。
- **condition 存续**：注册表可选字段 {path, op, value}（模板路径），纯内容侧——对象侧永不挂载；等级组内 ∨ 求值时按读者变量树求真，为真即计入 matched；对全知读者跳过求值。挂载档位收编"算必要还是充分"的旧歧义：挂一级 = 充分，挂二级 = 必要。
- **注册表条目 = {name, description?, condition?, category?, system?}**，名称即键：category = 封闭枚举 {cid, channel, location}，有类别的按类别声明登记（实例合法性程序判定：cid = 演员表存在、channel = 活跃频道、location = 某角色当前地点名；实例值 GM 经变量注入可见，不重复登记），无类别按名称登记；system = 程序化只读参考（加载校验与代码常量一致，任何层不得占用同名）。
- **ID 体系废除**：无挂点 ID、无选择器、无对象侧必要逻辑。排除语义 = 内容挂二级 TAG + 被排除者不持有（多数派持有）。

**为什么**：

- 充分/必要命名废止："必要"与"有我就够了"的直觉相反（多一个必要 TAG 反而只有它不够）；等级表达式把组合规则化为 ∧(∨) 统一形式，且向更多级开放。等级做成挂载属性而非 TAG 本质属性：等级划分对对象侧无意义，GM 只管往角色身上挂纯名称。
- 对象侧逻辑检查移除 → ID 体系失去存在理由：一次 TAG 输出挂载的代价远小于提示词混入无穷无尽的无序数字（无逻辑 ID 稀释 LLM 质量，有逻辑 ID 诱发幻觉自创）。排除场景的多数派补 TAG 成本主要落在 lore 上，而 lore 维护不在 GM 职责内，不增加 GM 工作量。
- 虚拟挂载按非空等级组而非全内容：全内容挂载会让无 TAG 内容判别式变非空，恒通过（广播）报废。
- 归一化而非通配/有序子集匹配：占位符作者无法预知运行期 CID/频道号/地点名；由过滤系统把开放类别命中归一化为固定记号后，分支键保持字面精确集合，精确匹配纪律完整保住。
- 广播/强制广播、全知/强制全知的二分废弃：对象侧无等级，不存在从对象侧拒绝广播的手段；强制级差由全知/强制全知的等级位置表达。
- 反 TAG 家族（反映射/反广播/反全知）不设：靠同名建立对应关系，命名语义必然在一侧颠倒，损害 GM 判决质量与可读性。

**代价**：

- 排除信息寄生在多数派（被排除者不挂、其余人挂），成本与多数派规模成正比；热生成角色的默认方向靠提示词教学缓解（新角色默认补挂常识类二级 TAG）。
- 组合表达力封闭在两级："必须同时满足多个条件"靠升二级组表达，更复杂的组合暂不可表达（刻意封闭，需要时再扩级）。
- "每角色每开放类别至多一个"由程序安插维持；世界作者手工给角色挂第二个同类 TAG 无机制防护（注册表只有类别声明，校验无处可挂）。
