# TAG 逻辑代数：等级表达式，等级是内容侧挂载属性

**决定**：

- **判定式纯内容侧**：内容侧每个 TAG 挂载 = {name, level}，level ∈ {1..7}（封闭）；T =（一级组取 ∨）∧（二级组取 ∨）∧ … ∧（七级组取 ∨）；空等级组不产生约束；无 TAG 内容判别式为空 = 恒通过（广播语义，不设独立广播/强制广播逻辑）。同级 = 或、跨级 = 与："必须同时持有 A、B、C" = A/B/C 分挂三个等级。对象侧 = 纯名称集合（落盘 ∪ 程序派生），无等级——GM 授予/摘除角色 TAG 的裁决包字段 = 纯字符串数组。
- **等级与 TAG 身份解绑**：等级是挂载处的可调属性，不进注册表；结构附加默认一级，GM/世界作者加挂选等级（或 = 同级、与 = 跨级，教学归提示词设计）。
- **全知 = 全知权重 + 虚拟挂载**：全知权重 = 角色恒定变量（系统字段，值域 0-6，0 = 常规角色），是全知覆盖面的唯一语义来源——对象侧不挂字面"全知"TAG，matched 的"全知"记号由权重派生。求值时（不落盘）按读者权重对每一级 ≤ N 的非空组追加虚拟"全知"；**强制全知只对七级非空组追加**，仅 GM 持有（GM 与正文 = 权重 6 + 持强制全知 = 全集可见；正文 = 全知读者）。**全知打破**：对权重 N 的角色隐瞒 = 内容挂一个 N+1 级 TAG；GM 永不可被打破（不存在 8 级）。保留强制全知 TAG 而非开放权重 7：GM 与一般全知对象可采用不同提示词/分支。
- **匹配扁平**：等级只参与判定式；matched 从对象侧持有出发取交集——读者的单个"全知"对内容侧多个等级的虚拟挂载逐一命中，matched 中"全知"天然只出现一次（不是多个命中去重）。
- **过滤返回 = {status, content, matched}**：status = pass/fail 显式枚举（不靠空内容推断——放行且内容为空是合法结果）；matched = 双侧共同持有记号集（含虚拟挂载），去重排序。开放类别归一化：category ∈ {cid, channel, location} 的命中一律报类别固定记号——每角色每类至多持有一个（cid = 自身 CID，唯一；channel = 当前频道编号；location = 当前地点名，后两者程序随变量持久安插），归一化无损。
- **condition 存续**：注册表可选字段 {path, op, value}（模板路径；op 封闭枚举 eq/ne/lt/le/gt/ge/between/contains，fail-closed），纯内容侧——对象侧永不挂载；等级组内 ∨ 求值时按读者变量树求真，为真即计入 matched；组被虚拟挂载覆盖（全知权重 / 强制全知）时跳过该组 condition 求值。condition 的与/或语义由挂载等级表达（同级 = 或、跨级 = 与）。
- **注册表条目 = {name, description?, condition?, category?, system?}**，名称即键：category = 封闭枚举 {cid, channel, location}，有类别的按类别声明登记（实例合法性程序判定：cid = 演员表存在、channel = 活跃频道、location = 某角色当前地点名；实例值 GM 经变量注入可见，不重复登记），无类别按名称登记；system = 程序化只读参考（加载校验与代码常量一致，任何层不得占用同名）。
- **ID 体系废除**：无挂点 ID、无选择器、无对象侧必要逻辑。排除语义 = 内容挂跨级 TAG + 被排除者不持有（多数派持有）。

**为什么**：

- 等级表达式把组合规则化为 ∧(∨) 统一形式：同级或、跨级与，"需要同时拥有 ABC 才能看到" = 分挂三级；7 级对现实需求（一般不超过四 TAG 相遇）绰绰有余且保持封闭。等级做成挂载属性而非 TAG 本质属性：等级划分对对象侧无意义，GM 只管往角色身上挂纯名称。
- 对象侧逻辑检查移除 → ID 体系失去存在理由：一次 TAG 输出挂载的代价远小于提示词混入无穷无尽的无序数字（无逻辑 ID 稀释 LLM 质量，有逻辑 ID 诱发幻觉自创）。排除场景的多数派补 TAG 成本主要落在 lore 上，而 lore 维护不在 GM 职责内，不增加 GM 工作量。
- 全知权重取代固定档位：权重管 1-6 级、强制全知管 7 级，结构齐整——打破规则 = N+1，GM 永不打破；"系统流"叙事（系统是全知 NPC 但被高位面隐瞒）= 权重 1-6 的角色。权重是唯一语义来源（而非对象侧挂字面"全知"TAG）：覆盖面是数值属性，TAG 持有与权重值双数据源必然打架。
- 虚拟挂载按非空等级组而非全内容：全内容挂载会让无 TAG 内容判别式变非空，恒通过（广播）报废。
- 归一化而非通配/有序子集匹配：占位符作者无法预知运行期 CID/频道号/地点名；由过滤系统把开放类别命中归一化为固定记号后，分支键保持字面精确集合，精确匹配纪律完整保住。
- 广播/强制广播、全知/强制全知的二分废弃：对象侧无等级，不存在从对象侧拒绝广播的手段；强制级差由全知权重与强制全知的等级位置表达。
- 反 TAG 家族（反映射/反广播/反全知）不设：靠同名建立对应关系，命名语义必然在一侧颠倒，损害 GM 判决质量与可读性。

**代价**：

- 排除信息寄生在多数派（被排除者不挂、其余人挂），成本与多数派规模成正比；热生成角色的默认方向靠提示词教学缓解（新角色默认补挂常识类跨级 TAG）。
- 组合表达力封闭在七级 ∧(∨)：任意布尔组合不可表达（刻意封闭，需要时再扩级）。
- GM 挂 TAG 需选等级（1-7），认知负荷高于"或/与"二分；靠提示词教学（或 = 同级、与 = 跨级、打破 = N+1）与结构附加默认一级缓解。
- "每角色每开放类别至多一个"由程序安插维持；世界作者手工给角色挂第二个同类 TAG 无机制防护（注册表只有类别声明，校验无处可挂）。
