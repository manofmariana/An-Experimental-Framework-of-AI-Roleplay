# 功能提示词组封闭；输入模式 = 模板 × 占位符位置

**决定**：对象 × 功能矩阵的两个轴都封闭——对象清单由代码枚举（新对象 = 新 activation 种类，是开发行为），功能组也不支持用户增删；WebUI 两级页面编辑的是既有功能组的模板内容，不是矩阵结构本身。功能选择权永远在程序（管线步类型 / 显式指令 → 功能组的映射表在代码里），模型无权自选。三种输入模式（主控/上帝/写作）归约为**两套功能模板（主控、上帝）**：写作指令与上帝模式注入都是工作集的一部分，即内容单元，由占位符渲染——写作指令注入给谁、注入在哪，纯粹是组装时占位符放在哪个模板的哪个位置的问题，不设第三套机制。

**为什么不开放功能轴、不设"追加模块"机制**：功能组若开放增删，就需要让用户理解"哪个情境激活哪组"的程序映射，复杂度转移到了最不该承担它的地方；封闭后矩阵是一张可穷举、可测试的表。写作指令若走"整组切换"会让"裁决 × 写作指令"这类正交组合复制整套模板；若走"追加模块"则多一套机制——而它本质是一段内容（工作集条目），内容就该走内容单元 → 占位符的既有通道，注入位置由模板决定。

**代价**：新增输入模式或新对象功能 = 改代码（模板文件 + 映射表），不能纯配置扩展。
