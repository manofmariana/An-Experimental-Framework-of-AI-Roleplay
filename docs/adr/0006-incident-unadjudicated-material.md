# 突发事件不落事件库（未裁决素材模型）与 kind/身份分离

**决定**：突发事件系统（概率激活长期休眠组，机制见 DESIGN.md §4.8）采用两个结构决定。①突发 GM 的产出**不落 Event**——事件文本作为**未裁决素材**存于 incident 归档步的 result（地位同工作集），经派生注入目标组角色的 #当前场景 开头与常规 GM 的 ##当前场景 开头；GM 结算覆盖该组时将其转写为真正的 Event，注入自动消解。②归档步新增 kind `"incident"`，但 agent **身份仍是 GM**（同一 preset、同一全知视野）；输出契约为 slim（事件文本 + 可选 deltas），不复用 durations 覆盖校验。

**为什么突发事件不落 Event**：Event 是 GM 裁决的产物——真相层只记已裁决的事实。突发 GM 只创作"发生了什么"，而事件的完整内容 = 突发本身 + 被激活组的反应，二者必须一起裁，裁决权属于之后那次常规 GM。突发文本若直接落 Event，未经互动裁决的文本就成了真相，还要为它的可见性（感知 TAG）与消解单建机制。未裁决素材模型复用工作集哲学：注入但不污染真相，消解靠结算自然发生（零清理特例），回溯随步截断白拿。

**为什么 kind 与身份分离**：归档 kind 是管线语义轴（调度透明、正文取材边界、回溯单元），身份是模型预设轴（用哪个模型跑）——系统已有先例（player 步无身份）。突发 GM 需要与 GM 完全相同的全知视野（lore 全文、演员表、事件流）才写得出贴合的突发事件：它是同一颗心换一套提示词组，"同一身份 × 不同功能 = 不同提示词组"的首个实例；独立成第四身份只会徒增配置面（第四个 preset 绑定与配置 UI）且语义错误。kind 不复用 `"gm"`，因为 currentAdjudication/roundSteps 按 `"gm"` 找正文取材边界，突发步混入会让正文错抓突发包；slim 契约不复用 durations 覆盖校验，因为语义不通——被打断的组是被拉回现在（timer 对齐时钟），不是被推入未来。

**为什么命中评估自变量 = 剩余休眠时长（timer − clock）**：机制目的 = 激活长期搁置的组，剩余时长越深 = 被搁置得越久；且它是唯一纯派生可用的自变量——组是派生状态、不持有任何变量（adr/0005），"原始 span"或"已搁置经过时长"都要破这条纪律落盘存储。

**代价**：被命中组成员的感知不走事件 TAG 过滤通道（adr/0002）——注入层为未裁决素材新开一个派生源（与 adr/0002 是补充而非冲突：TAG 过滤仍管已裁决 Event，未裁决素材本就不在事件库）；archive 新增一种步 kind，凡按步 kind 分派处（历史投影/正文取材/编辑回放）都要认识它；命中评估挂在每次常规 GM（及正文）结束后，评估频率与世界活跃度耦合，概率函数标定须计入评估次数的复利效应。
