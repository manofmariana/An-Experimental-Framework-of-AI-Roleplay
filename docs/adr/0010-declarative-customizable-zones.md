# 前端可定制区 = 声明式模板 + 部件库扩展通道

**决定**：工具 Agent 可写的前端区域（侧边状态栏、底部状态栏）只接受**声明式模板**（数据：绑定 + 条件 + 重复，无脚本能力），多文件拆分 + Agent 访问路径白名单；区域限制是**逻辑限制**——Agent 不得改动两栏以外的任何内容，但栏内组件可以覆盖全页面（全屏特效是状态栏自己的组件）。表达力扩展走**框架内置部件库**（图表/音频触发/浮动数字/倒计时等可绑定部件，全体世界观共享）；部件库未覆盖的新交互范式 = 框架区功能开发（人类或外部 Agent）。框架区 = 代码，可定制区 = 数据。

**为什么不允许自由 JS**：可写 JS 即拿到整个页面 DOM，"两级物理隔离"就降级为一纸约定；声明式模板把隔离变成结构事实（模板引擎没有手）。真正需要自由代码的功能（Canvas 绘制、音频、时间驱动、自定义输入、第三方可视化）全是通用能力而非某世界观专属逻辑——通用能力就该做成共享部件库，而不是让 Agent 在存档里写野生 JS。

**代价**：可定制区表达力上限 = 模板引擎 + 部件库的覆盖范围；新交互范式落地需要框架区开发周期，不能即想即有。
