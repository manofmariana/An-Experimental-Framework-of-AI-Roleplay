# 事件感知走逻辑 TAG：内容侧挂载 + 类别化匹配 + 程序补全

**决定**：

- 事件感知过滤 = TAG 等级表达式求值（adr/0007）：Event 与 GM 裁决包事件的 tags = 内容侧挂载 `{name, level}[]`（level 1-7，范围 schema 机检）；location 只是叙事记录字段，不参与感知过滤。
- 常规可见性 = cid 类 TAG：GM 为实际感知者挂 `{name: 裸 CID, level: 1}`。读者有效 TAG 集 = 落盘池 ∪ 程序派生（自身 cid 恒在），cid 命中归一化为类别记号；私密事件 = 只挂自身 cid。
- GM 输出 = 结构化数组直出（等级选择教学归提示词：同级 = 或、跨级 = 与）；**空数组 = 程序补全本轮全部行动者的 cid 类 TAG（level 1）**（唯一写入点 = GM 裁决规划器，语义与 GM 默认全标等价）。
- 裁决包 tags 名称校验 = 档内注册表类别化口径（注册名 ∪ cid 现存实例 ∪ channel/location 声明，与变量写值同一口径），不合法走解析失败拒绝重试通道。
- 两个过滤点（事件库 `readVisibleTo` 与调度纯逻辑副本 `visibleEvents`）同走 `evaluateTagFilter`，读者上下文与注册表均由调用方注入；GM/正文侧不过滤（权重 6 恒过，投影层维持全量取数）。

**为什么**：`known_by:CID` 扁平标签是等级表达式的特例（一级组取 ∨ ≡ 命中任一即收录，语义严格等价）。统一走 TAG 代数后，事件获得完整组合表达力（跨级 = 与、全知权重覆盖、condition），感知与 lore/变量共用同一求值器、同一注册表、同一名称校验口径，不再维护第二套标签语义。无地点成分的理由不变：GM 标记时已基于推理考虑了各角色的可视情况（谁在场、谁参与对话、私密事件只标自己），机械地点匹配会对跨场景对话制造假阴性。

**代价**：GM 需选等级（认知负荷靠提示词教学与"一般只用 1 级"缓解）；旧档不迁移（版本闸拒装）。
